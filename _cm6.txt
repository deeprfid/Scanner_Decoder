fix(boot): boot 用专用 lib（hc32f46_boot.lib，IS_RTOS2_SUPPORT=0）解决 main.o 冲突

- 根因链：
  1. hc32f46_driver.lib 用 IS_RTOS2_SUPPORT=1 编译（App 配置），含 main.o
  2. boot 链接它 + 自己编译 main.c -> main/__ARM_use_no_argv 重复定义
- 项目构建说明：boot 需 IS_RTOS2_SUPPORT=0 的 lib（main.c 的 main 在 #if IS_RTOS2_SUPPORT 内，=0 时跳过 -> lib 不含 main）
- 方案（遵循构建说明）：
  - 新增 tools/build_boot_lib.py：临时切 driverconfig.h 宏（IS_RTOS2=0, ICG=1）-> UV4 编译 driver -> 存 driver_lib/hc32f46_boot.lib -> 恢复宏（IS_RTOS2=1, ICG=0）
  - boot uvprojx 链接 hc32f46_boot.lib（不再用共享 hc32f46_driver.lib）
  - build_release_f460.py 构建顺序：driver(App配置) -> build_boot_lib -> boot -> app
- 撤销：boot 自包含方案（去 lib 加 efm/icg）已回退——boot 依赖 lib 的 QSPI/GPIO/PWC/串口等 31 个符号，补源码不现实
- boot uvprojx 恢复 24169ef 版（链接 lib）+ 头文件 hc32f46x_icg.h/hc32f46x_efm.h 拷入 user/inc（icg.c 需要）
